# Local Proctoring

[English](README.md) | **Русский**

В Git включены `config/default.example.toml` и
`config/protected-demo.example.toml`. Рабочие `default.toml` и
`protected-demo.toml` остаются локальными и исключены через `.gitignore`.
Данные калибровки, готовые PDF, записи сеансов и результаты brag в коммит не входят.

Готовые **EXE и config.toml скачивайте вместе** из
[GitHub Releases](https://github.com/kutenchik/proctoring/releases).
В конфиге релиза удалённая отправка выключена, реквизиты очищены,
демонстрационный PIN — `739261`. Замените его перед экзаменом.
EXE распространяется как вложение релиза, а не как файл в Git.

Локальное настольное приложение для демонстрации прокторинга на Windows 10/11:
камера, калибровка взгляда, обнаружение телефона и людей, тест, журнал событий
для проверки проктором и необязательный защищённый режим Windows. Основной
сценарий — управляемый университетом компьютер и контролируемая демонстрация.
Приложение работает на CPU; видеокарта NVIDIA не требуется.

Результаты обнаружения — **поводы для проверки человеком**, а не доказательство
списывания. Это прототип, а не сертифицированная система контроля экзаменов.
Инструкции ниже описывают текущую реализацию, включая переносимую EXE-сборку,
адаптивную проверку микрофона и необязательные внешние сервисы.

## 1. Возможности и границы проекта

| Подсистема | Реализованное поведение |
| --- | --- |
| Регистрация | Имя, фамилия, группа/ID студента; привязка к записям сессии. |
| Камера | Одна встроенная или USB-камера, фоновые захват и обработка, актуальный кадр без очереди старых кадров. |
| YOLO11n | Классы COCO `person` и `cell phone` через локальный ONNX Runtime. |
| MediaPipe | Ориентиры лица, геометрия радужек/век и отдельная оценка положения головы. |
| Калибровка | Индивидуальные для сессии ориентиры CENTER/LEFT/RIGHT/DOWN с проверкой качества. |
| Тест | Встроенные вопросы с вариантами ответов либо разрешённый внешний сайт во встроенном браузере. |
| Мониторинг | Камера, рамки объектов, взгляд, положение головы, состояние обработки, FPS и задержки. |
| События | Пороги по длительности, гистерезис завершения, одно активное событие на устойчивое наблюдение. |
| Материалы | JSON/JSONL, необязательные JPEG при активации события, итоговый PDF. |
| Микрофон | RMS-индикатор, измерение фона, проверка звукового отклика и настройка чувствительности. |
| Защита | Необязательные временные ограничения Windows после независимой проверки восстановления. |
| Интерфейс | Английский, русский и казахский с переключением без перезапуска. |
| Доставка | Необязательная фоновая отправка в Telegram и/или HTTP webhook. |

Целевое оборудование: Windows 10/11 x64, современный Intel/AMD CPU, минимум
8 ГБ ОЗУ, одна камера; 720p достаточно. Для запуска из исходников используется
64-разрядный Python 3.11. Микрофон нужен только для включённого аудиомониторинга.

Видеопоток обрабатывается локально. Непрерывная запись видео и аудио отсутствует.
Внешний LMS получает данные, введённые на его сайте; включённая удалённая доставка
передаёт выбранным получателям сведения о кандидате и сохранённые материалы.
Интеграции API для оценок и отправки ответов в LMS нет.

## 2. Запуск переносимой EXE-сборки

Готовая сборка находится в `dist/LocalProctoring/`:

```text
LocalProctoring/
├── LocalProctoring.exe
└── config.toml
```

1. Скопируйте **оба файла вместе** в доступную для записи папку на Windows.
2. Откройте `config.toml` текстовым редактором и проверьте нужные параметры.
3. Запустите `LocalProctoring.exe` двойным щелчком.
4. При включённой защите дождитесь автоматической проверки восстановления.
5. Пройдите регистрацию, настройку камеры и калибровку; начните экзамен.

Python, Qt/WebEngine, OpenCV, ONNX Runtime CPU, MediaPipe, поддержка микрофона,
переводы, встроенный тест и две модели включены в EXE. Отдельно устанавливать
Python или скачивать модели перед каждым запуском не нужно. EXE сборки от
7 октября 2026 года занимает примерно 339 МБ, или 324 МиБ. При первом запуске
распаковка Qt и моделей во временную папку может занять заметное время.

Рядом с конфигурацией создаются папки сессий и результатов проверки защиты.
Это выходные данные; требование «два файла» относится к поставке приложения.
Редактирование настроек применяется после перезапуска. Пути `@bundle/...`
обозначают встроенные ресурсы; обычные пути позволяют использовать свои файлы.

Сборка использует копию `config/protected-demo.toml`, а не обязательно настройки
из `config/default.toml`. В поставленной сборке от 7 октября аудио выключено.
Чтобы включить виджет микрофона, измените **существующую** секцию:

```toml
[audio]
enabled = true
```

Не создавайте вторую секцию `[audio]`. В конфигурации могут быть PIN и реквизиты
удалённой доставки оператора: проверьте файл перед передачей другим людям.
EXE не имеет цифровой подписи. Для обычного запуска установка с правами
администратора не требуется. Подробности: [WINDOWS_BUILD.md](docs/WINDOWS_BUILD.md).

## 3. Установка и запуск из исходников

Команды выполняются в PowerShell из корня проекта. Ниже приведён текущий
локальный путь; на другом компьютере замените его путём своего проекта.

```powershell
Set-Location 'C:\Users\kuten\Desktop\case3_proctoring'
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
.\.venv\Scripts\python.exe scripts\fetch_models.py
if (!(Test-Path config\default.toml)) { Copy-Item config\default.example.toml config\default.toml }
if (!(Test-Path config\protected-demo.toml)) { Copy-Item config\protected-demo.example.toml config\protected-demo.toml }
.\.venv\Scripts\python.exe -m proctoring
```

Редактируйте созданные копии, а не файлы `.example.toml`.
В обычном примере защита Windows выключена; в защищённом — включена и требует
проверки восстановления. Оба примера используют встроенный тест и не отправляют
данные удалённо. Автотесты читают примеры из Git и не требуют личных конфигов.

Установка зависимостей и первое получение моделей требуют сети, если файлы
не подготовлены заранее. Скрипт моделей проверяет закреплённые SHA-256.
Во время работы vision-подсистема ничего не скачивает автоматически.

Для встроенного браузера установите официальный пакет Qt WebEngine:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.lock
```

Основной lock-файл уже включает HTTP-клиент и `sounddevice`. Запускайте через
Python из `.venv`, чтобы случайно не использовать другое окружение.

```powershell
# Собственная полная конфигурация
.\.venv\Scripts\python.exe -m proctoring --config C:\path\demo.toml

# Искусственные наблюдения без камеры
.\.venv\Scripts\python.exe -m proctoring --synthetic

# Диагностика калибровки; защита Windows должна быть выключена
.\.venv\Scripts\python.exe -m proctoring --calibration-debug

# Подготовка и запуск защищённой демонстрации
.\.venv\Scripts\python.exe scripts\validate_protection.py
.\.venv\Scripts\python.exe -m proctoring --config config/protected-demo.toml
```

`config/default.toml` и `config/protected-demo.toml` в рабочей копии уже могут
быть изменены оператором. Имя файла не гарантирует отключение защиты, сети или
других опций. Перед локальной отладкой проверьте `protection.enabled = false`
и `remote.enabled = false`. Синтетический режим заменяет источник vision-
наблюдений, но сам по себе не отключает все остальные настроенные подсистемы.
Для полностью локальной проверки без камеры, микрофона и внешнего сайта
дополнительно выключите `audio.enabled` и
`exam.identity.selfie_verification_enabled`, оставьте `exam.external_url = ""`.

## 4. Порядок работы студента и проктора

1. **Регистрация.** Введите имя, фамилию и группу/ID. Обязательные поля не могут
   содержать только пробелы. Если регистрация отключена, откроется настройка.
2. **Необязательное эталонное фото.** При включённой проверке личности откройте
   камеру и сделайте фото с одним хорошо видимым фронтальным лицом.
3. **Камера.** Нажмите кнопку открытия камеры, дождитесь живого изображения и
   готовности мониторинга. Разместите лицо внутри неподвижного овала.
4. **Микрофон.** Если аудио включено, проверьте индикатор, измерьте тихий фон
   и произнесите несколько слов по инструкции. Этот шаг не блокирует экзамен.
5. **Калибровка взгляда.** Нажмите «Начать калибровку» один раз и следуйте
   автоматической последовательности CENTER → LEFT → RIGHT → DOWN.
6. **Начало.** После успешной калибровки и выполнения включённых проверок
   нажмите «Начать экзамен». Защита Windows, если настроена, включается здесь.
7. **Прохождение.** Отвечайте во встроенном тесте или на внешнем сайте. Панель
   мониторинга и журнал остаются рядом; предупреждения не останавливают время.
8. **Пауза.** Проктор может приостановить экзамен через PIN. Сбой камеры или
   vision-пайплайна приостанавливает экзамен автоматически.
9. **Завершение.** Проктор завершает сессию через PIN. Ограничения снимаются до
   остановки камеры и сохранения итога; при истечении времени сессия также завершается.
10. **Проверка.** Просмотрите итог, локальный журнал, снимки и PDF, если включён.

PIN задаётся в приватной конфигурации; этот README не публикует рабочий PIN.
**Ctrl+Shift+Alt+Q** — внутренний способ аварийного снятия ограничений при
зависании или проблеме демонстрации. Он не предназначен как обычная кнопка
выхода студента. После аварийного освобождения ограничения не включаются сами.

## 5. Положение лица и калибровка взгляда

Овал фиксирован относительно области реального изображения с учётом масштаба
и чёрных полей. Он не следует за лицом и не меняет размер под лицо. Янтарный
цвет обозначает неготовность, зелёный — подходящее положение. Во время экзамена овал скрыт.

Перед сбором проверяются наличие лица, его положение и размер в исходном
кадре, видимость обоих глаз, приблизительно фронтальная поза и кратковременная
стабильность. Типовые значения: лицо не менее 140×160 пикселей, каждый глаз
не менее 32 пикселей шириной, yaw/pitch до 15°, roll до 12°, стабильность
0,75 секунды и минимум три свежих измерения. Внутренняя проверка размещения
использует практическую геометрическую область; рисуемый овал — подсказка.

Сообщения «Приблизьтесь», «Расположите лицо по центру», «Держите оба глаза
видимыми», «Не двигайтесь» и «Лицо в зоне» показывают текущую причину. Готовность
положения лица не означает, что направления взгляда уже различимы.

### Автоматический сбор четырёх направлений

| Цель | Куда смотреть |
| --- | --- |
| CENTER | На отметку в физическом центре экрана. |
| LEFT | Немного за левую физическую границу экрана. |
| RIGHT | Немного за правую физическую границу экрана. |
| DOWN | Ниже нижней физической границы экрана, не на кнопку приложения. |

Каждая цель имеет подготовку 2 секунды, звуковое начало и завершение сбора.
Номинально сбор длится 3 секунды. Если 20 валидных свежих измерений ещё нет,
окно продлевается максимум до 6 секунд; дедлайн не сдвигается из-за ошибок.
Устаревшие и повторные кадры не добавляют образцы. Сильная смена положения
очищает несовместимые незавершённые измерения. Повтор текущей цели заменяет
её данные, сохраняя завершённые совместимые цели; новый базовый проход
сбрасывает ссылки явно. Смена камеры или прерывание мониторинга обнуляет базу.

Моргайте естественно, сохраняйте удобную позу и необходимые корректирующие
очки. Кратковременно невалидный глаз исключает образец взгляда, но не стирает
независимо подтверждённую стабильность лица. Для новой посадки, освещения или
условий очков собирайте новую базу. Не нужно сильно поворачивать голову.

### Что классифицирует приложение

MediaPipe возвращает ориентиры и преобразование лица, **а не готовые метки
взгляда**. Положение радужки вычисляется относительно оси уголков глаза и
нормируется на ширину глаза. Ссылки направлений индивидуальны для сессии.
Разделимость проверяется с учётом разброса, постоянного и пиксельного порогов;
вклад предполагаемой пиксельной неопределённости настраивается.

Защищённое дополнение DOWN использует вместе вертикальное смещение радужки
и относительную открытость век по отношению к CENTER. Маленькая открытость
сама по себе не означает DOWN. Закрытые, неразличимые, неоднозначные глаза или
ненадёжная геометрия дают `UNKNOWN`, а не фиктивный CENTER. Успешная калибровка
не является доказательством точности на обычном чтении.

Отдельный признак **`head_down`** описывает позу головы: после принятой
калибровки, при видимом лице и актуальной конечной оценке позы,
`14 < pitch < 90`, `abs(yaw) <= 15`, `abs(roll) <= 12` градусов. Он может
поддержать существующее событие `gaze_down`, даже если глаза дают UNKNOWN.
В интерфейсе поза и глазной взгляд остаются разными сигналами; уверенность
для головы не выдумывается. Это эвристика для проверки, не обнаружение телефона
или чтения конспекта. Угол зависит от расположения камеры.

### Диагностика и самостоятельная проверка

Режим `--calibration-debug` при выключенной защите показывает размеры кадра,
ширины глаз в исходных пикселях, открытость, осевые медианы/разбросы, составляющие
порогов и причины отклонения. Неудачный проход можно исследовать и экспортировать
без успешной калибровки. Числовой JSON сохраняется только после явного включения
экспорта; фотографии и видео этой функцией не сохраняются.

Выбранная попытка и источник замороженных ссылок отдельного validation-прохода
имеют идентификаторы. Не сравнивайте очки/без очков как независимые условия,
если оба файла ссылаются на одну базу. Не называйте UNKNOWN правильным ответом.
Свежая последовательность CENTER/LEFT/RIGHT/DOWN/READING проверяет уже
замороженные ссылки; DEBUG / UNVALIDATED не открывает доступ к экзамену.
Опциональные крупные планы глаз используют соответствующий исходный кадр
с ориентирами: увеличение не добавляет деталей и не определяет блики автоматически.

Практические инструкции: [сбор](docs/CALIBRATION_COLLECTION.md),
[размещение лица](docs/FACE_ALIGNMENT.md), [диагностический проход](docs/GAZE_DIAGNOSTIC_RUN.md),
[видимость глаз](docs/EYE_VISIBILITY_CHECK.md), [поза головы](docs/HEAD_DOWN_POSTURE.md).

## 6. Проверка и калибровка микрофона

При `audio.enabled = true` после регистрации появляется индикатор RMS с
зелёно-жёлто-красной шкалой, отметкой текущего порога, числовыми значениями,
кнопкой калибровки и ползунком чувствительности. Уровни обновляются до 20 раз
в секунду. Чтение монофонических буферов по 50 мс выполняет фоновый поток.

1. Нажмите **Calibrate Mic / Калибровать микрофон**.
2. Сохраняйте тишину **2,5 секунды**: измеряется медиана RMS окружающего шума.
3. По просьбе произнесите несколько слов обычной громкостью. Нужен сигнал
   выше предложенного порога минимум **0,15 секунды** в течение **8 секунд**.
4. Зелёное сообщение готовности подтверждает рост энергии, а не распознавание речи.
5. При необходимости измените чувствительность и повторите проверку.

```text
recommended_threshold = max(ambient_RMS * 2.5, ambient_RMS + 0.08)
```

Порог — абсолютная нормированная амплитуда RMS, не дБ и не вероятность речи.
По умолчанию допустим диапазон 0,05–0,40. Если сам фон требует порог выше
максимума, приложение сообщает о слишком шумной среде, а не принимает
заведомо низкий порог. Высокая чувствительность снижает порог, низкая повышает;
ползунок не меняет аппаратное усиление Windows. Ручное изменение после успеха
снимает отметку подтверждённой готовности до следующей проверки.

Адаптивный/ручной порог сохраняется в памяти активной сессии и в числовых
метаданных. Неудачный повтор сохраняет ранее принятый порог с отдельным
указанием источника. Без принятой настройки действует прежний запасной режим:
3 секунды обучения фону и `max(ambient + energy_threshold, 3 * ambient)`.
`energy_threshold = 0.15` здесь является добавкой, а не абсолютным адаптивным порогом.

Нет устройства, нет разрешения, устаревшие данные, переполнение входа и отсутствие
достаточного всплеска показываются явно. Повтор подключения доступен через UI.
Неисправность микрофона **не блокирует начало и не приостанавливает экзамен**;
камера продолжает работать. При начале экзамена старые звуковые наблюдения
отбрасываются, а элементы настройки блокируются. Только свежий звук экзамена
может накопить двухсекундное событие `VOICE_DETECTED`.

Записи и отправки аудио нет. RMS не отличает речь от музыки, вентилятора или
другого шума; пользовательская метка описывает устойчивую звуковую активность.
Подробнее и аппаратный тест: [AUDIO_CHECK.md](docs/AUDIO_CHECK.md).

## 7. Встроенный тест и внешний экзамен

При пустом `exam.external_url` используется встроенный тест с шестью вопросами,
вариантами ответов, локальным таймером и итогом. Свой JSON выбирается через
`quiz_path`; используйте структуру [assets/quiz.json](assets/quiz.json), уникальные
идентификаторы вопросов, минимум два варианта и корректный индекс ответа.
Переводы встроенных демонстрационных вопросов не переводят произвольный свой тест.

Внешний режим включается URL в существующей секции:

```toml
[exam]
duration_seconds = 600.0
quiz_path = "../assets/quiz.json"
external_url = "https://moodle.university.edu/mod/quiz/view.php?id=123"
allowed_domains = ["moodle.university.edu", "login.university.edu"]
```

Пустой `allowed_domains` разрешает точное имя хоста из `external_url`. Если
авторизация уходит на другой университетский хост, добавьте его явно.
Элементы списка — только имена хостов без схем, путей и `*`; поддомены
автоматически не разрешаются. Контролируются переходы основного документа
и дочерних фреймов. Ресурсы CDN могут загружаться: это не сетевой экран.

Страница загружается после успешной подготовки и начала экзамена. Контекстное
меню, дополнительные окна/вкладки, скачивания, F12 и Ctrl+Shift+I блокируются.
Разрешения браузера на камеру, микрофон и экран отклоняются; данные CV сайту
не передаются. Профиль браузера хранится в памяти текущего запуска.

Локальная пауза отключает взаимодействие со страницей, но не останавливает
серверный таймер LMS. Сетевая ошибка страницы не становится ошибкой камеры;
доступна перезагрузка. Сначала отправьте ответы на сайте, затем завершите
локальную сессию через проктора. Приложение не подтверждает внешнюю оценку
или успешную отправку. Вход с popup/SSO может быть несовместим: заранее
проверьте авторизацию, разрешённые переходы и сдачу на конкретной платформе.

## 8. События, таймер и восстановление мониторинга

| Наблюдение | Код события | Непрерывная длительность |
| --- | --- | --- |
| Видимый телефон | `phone_visible` | 1,0 с |
| Не менее двух достаточно крупных/уверенных людей | `second_person` | 1,0 с |
| Телефон поднят к области лица/верхней части тела | `phone_raised` | 1,25 с |
| Калиброванный взгляд в сторону/вниз или поддержанный наклон головы вниз | `gaze_left`, `gaze_right`, `gaze_down` | 3,0 с |
| Свежие кадры без основного лица | `face_absent` | 3,0 с |
| Необязательная устойчивая звуковая активность | `VOICE_DETECTED` | 2,0 с |
| Исчезновение условия активного события | Гистерезис завершения | 0,75 с |

Английское предупреждение поднятого телефона имеет точный текст:

> Phone raised — possible screen capture attempt.

Эвристика не проверяет направление камеры телефона, срабатывание затвора или
факт фотографии. Аналогично, наблюдение лица/объекта не устанавливает намерение.

Состояния события: **candidate → active → clearing → closed**. При устойчивом
наблюдении обновляются длительность и один ID; предупреждения и снимки не
создаются заново на каждом кадре. Краткий провал внутри гистерезиса сохраняет
событие. Только свежие наблюдения увеличивают подтверждённую длительность.
Продолжительности и таймер используют монотонные часы; календарное время нужно
для читаемых временных меток. Перебой мониторинга прерывает/сбрасывает
соответствующее состояние, не засчитывая время без наблюдений.

| Ситуация | Экзамен и таймер |
| --- | --- |
| Событие для проверки | Продолжаются. |
| Пауза проктора | Остановлены до возобновления с PIN. |
| Сбой камеры, устаревшие результаты/кадры, ошибка worker | Остановлены сразу после обнаружения сбоя. |
| Исправный мониторинг восстановился ранее 15,0 с | Автовозобновление, если нет другой причины паузы. |
| Восстановление через 15,0 с или позже | Нужен PIN проктора. |
| UNKNOWN взгляда при исправной обработке | Снижена доступность взгляда, остальные детекторы и таймер продолжаются. |
| Недоступный микрофон или ошибка отправки | Камера и таймер продолжаются. |

**14,9 секунды** допускают автоматическое продолжение; **ровно 15,0** уже
требуют PIN. Причины паузы независимы: восстановление камеры не отменяет паузу
проктора. Физическое отключение распознаётся по ошибке чтения либо пределу
свежести (типично 2 секунды для кадра/результата), а не обязательно мгновенно
в момент извлечения кабеля. При истечении времени сессия безопасно завершается.

## 9. Защита Windows и аварийное освобождение

Реальные ограничения включаются только через `[protection] enabled = true`.
Старое поле `[security] blocking_enabled` должно оставаться `false`.
Исходники запускаются после аудита, как показано выше; переносимый запуск
автоматически проводит тот же аудит при необходимости. Ручной вариант:

```powershell
.\LocalProctoring.exe --validate-protection
```

Аудит использует собственные временные окна и hook в режиме проверки: он
**не подавляет клавиши и не возвращает фокус из чужих окон**. Проверяются
независимое освобождение, аварийная комбинация, потеря heartbeat, завершение/
сбой родителя, повторные включения/отключения и работа PIN. Нужны все успешные
проверки, совпадающий отпечаток машины/сборки и отчёт моложе 24 часов.
Изменение кода, пересборка или перенос могут потребовать новый аудит.
Отчёт является условием восстановления демонстрации, а не защитой от подделки.

Ограничения начинают действовать после обычных условий старта и сохраняются
во время пауз. Отдельный временный Windows-процесс подавляет Alt+Tab,
Alt+Shift+Tab, обе Win, Ctrl+C/Ctrl+V, Ctrl+Insert/Shift+Insert, PrintScreen,
Alt+F4, Alt+Esc, Ctrl+Esc и Ctrl+Shift+Esc. Записываются названия комбинаций,
не введённый текст; удержание клавиш не создаёт поток повторных событий.

Окно полноэкранное, обычные попытки закрыть/свернуть перехватываются; PIN-диалог
принадлежит разрешённому процессу. Активация чужого окна фиксируется, возврат
фокуса выполняется по возможности. Другие приложения не завершаются.
События безопасности регистрируются сразу, без CV-порога по длительности.

**Ctrl+Shift+Alt+Q** действует локально в безопасном режиме и дополнительно
через глобальный независимый helper в защищённом режиме. Helper владеет hook
и получает heartbeat от прогресса UI. По типовым настройкам отсутствие
heartbeat освобождает ввод через 5 секунд; смерть родителя/закрытый канал
тоже снимают ограничения. Отдельная страховка остановившегося цикла завершает
helper через 3 секунды. Восстановление окончательно завершает защищённую
сессию: поздний heartbeat не включает блокировку повторно.

Завершение, выход по PIN, аварийное освобождение и очистка приложения снимают
защиту до операций камеры/диска. Реестр, автозапуск и политики Windows не меняются.
Ctrl+Alt+Del и защищённые рабочие столы Windows не блокируются. Возврат фокуса,
приложения с повышенными правами, удалённый ввод и альтернативный захват экрана
ограничивают возможности прототипа.

После успешного аудита доступны ограниченные по времени нативные тесты:

```powershell
.\.venv\Scripts\python.exe scripts\test_windows_protection.py --run
.\.venv\Scripts\python.exe scripts\test_protected_session.py --run
```

Каждая проверка использует собственные окна и не более пяти секунд ограничений.
Искусственный ввод не заменяет ручную репетицию аварийного выхода.

## 11. Дополнительная проверка личности и системы

Эталонное фото берётся из свежего согласованного кадра с результатом лица,
нормируется в квадратный JPEG 256×256 и привязывается к кандидату. Сравнение
использует нормированные 3D-ориентиры и остаточную ошибку после выравнивания
Procrustes. Это **не обученные биометрические эмбеддинги**: совпадение формы
не аутентифицирует человека, а выражение лица/поза/ошибка tracking могут дать
расхождение. Более трёх последовательных валидных несовпадений формируют
`IMPERSONATION_SUSPECTED`; невалидные сравнения сбрасывают серию.

Проверка мониторов учитывает экраны, видимые Qt, и при включении блокирует
старт с несколькими экранами. Это не полное обнаружение виртуальных дисплеев.
Защита буфера обмена очищает изменённое/непустое содержимое во время экзамена
и пишет `CLIPBOARD_ACCESSED`, не сохраняя скопированный текст.
Эвристика виртуальной машины исследует Windows BIOS/vendor и может записать
`VIRTUAL_MACHINE_DETECTED`; совпадение не блокирует экзамен автоматически.
Недоступность перечисления устройств не считается положительным результатом.

Эксперимент `EARPHONE_SUSPECTED` анализирует небольшие области рядом с щекой/
ухом и последовательность визуальных аномалий. MediaPipe не предоставляет
проверенную анатомию уха для этой задачи. Волосы, очки, тени и кожа могут дать
похожие признаки. Это неподтверждённая эвристика, не надёжный детектор наушников.

Эти переключатели сами по себе не включают клавиатурную защиту Windows.
Устройство проверок и ручные сценарии описаны в
[PROCTORING_EXPANSION.md](docs/PROCTORING_EXPANSION.md).

## 12. Локальные материалы, конфиденциальность и PDF

В настроенном каталоге результатов начавшаяся сессия обычно создаёт:

```text
sessions/<session_id>/
├── session.json              # Кандидат, идентификатор и параметры подготовки
├── config.json               # Публичная конфигурация без секретов
├── events.jsonl              # Заголовок сессии, события и жизненный цикл
├── summary.json              # Итог, время и завершённые события
├── snapshots/<event-id>.jpg  # Необязательные снимки событий
├── reference_face.jpg        # Явно запрошенное эталонное фото
├── remote_warnings.jsonl     # Необязательные предупреждения доставки
└── exam_integrity_report.pdf # Необязательный итоговый отчёт
```

Захват эталонного фото может создать каталог ещё до начала экзамена.
Дополнительные файлы появляются только при использовании соответствующей
функции. Непрерывные кадры/видео, аудиосэмплы и обычная калибровка взгляда не
сохраняются. Числовой developer-экспорт — отдельное явное действие; крупные
планы глаз для просмотра на диск не пишутся.

Ограниченная очередь фонового writer сохраняет один снимок на активацию
события при доступном подходящем кадре. В JSONL путь может сначала относиться
к ожидающей записи; итог содержит успешные пути и ошибки записи/переполнения.
Одновременные события могут иметь отдельные JPEG-файлы с одинаковым кадром.

PDF создаётся фоновым Qt-worker после локального итога. В нём есть кандидат,
сведения сессии/системы, эталонное фото при наличии и строка на каждое событие.
Миниатюры с сохранением пропорций встроены прямо в таблицу; отсутствующее
изображение помечается `No capture`. Время — `HH:MM:SS` в смещении исходной
временной метки; полные метки остаются в JSON/JSONL. Идентичные изображения
и наложения переиспользуют ресурс; дублирующей большой галереи нет. Типичный
короткий отчёт занимает 1–2 страницы, длинный журнал может занять больше.
Рамки в PDF наносятся на копию, исходные JPEG не изменяются.

Условный балл отчёта вычисляется правилом:

```text
max(0, 100 - 30*phone_events - 15*audio_events - 10*gaze_events - 50*identity_events)
```

Каждый уникальный ID учитывается один раз. Видимый и поднятый телефон — разные
типы событий, каждый может внести штраф. Балл 100 не доказывает отсутствие
нарушений или непрерывную исправность мониторинга.

PIN, токен бота, webhook token/полный URL и полный URL внешнего экзамена не
попадают в публичную конфигурацию сессии. Приватный TOML оператора сохраняет
введённые секреты. Локальные материалы не шифруются на диске, автоматическая
политика удаления не реализована. Назначьте доступ и срок хранения согласно
правилам учреждения; явно включённая доставка раскрывает перечисленные ниже данные.

## 13. Отправка в Telegram и webhook

Удалённый dispatcher дополняет локальный журнал. В исходном шаблоне без
секретов секция выглядит так:

```toml
[remote]
enabled = false
webhook_url = ""
webhook_token = ""
telegram_enabled = false
telegram_bot_token = ""
telegram_chat_id = ""
max_queue_size = 50
upload_timeout_seconds = 5.0
```

Для Telegram задайте токен, ID нужного чата/канала и права отправки боту,
затем включите `remote.enabled` и `remote.telegram_enabled`. Для webhook
задайте HTTP(S) URL и включите dispatcher; непустой token передаётся заголовком
`Authorization: Bearer ...`. Для удалённого получателя предпочтителен HTTPS.
Можно включить оба направления. При `remote.enabled = false` сетевой worker
не создаётся; включение без подходящего получателя не проходит валидацию.

| Тип доставки | Содержимое |
| --- | --- |
| `session_start` | Кандидат, группа, ID сессии, время начала; Telegram `sendMessage`. |
| `violation_alert` | Код/описание события, кандидат, длительность, время, доступная уверенность и снимок; `sendPhoto` либо сообщение. |
| `session_end` | Кандидат, ID, количество событий, длительность и причина завершения. |
| Итоговый PDF | Telegram `sendDocument`, если разрешены все нужные переключатели. |

Имя протокола `violation_alert` не означает доказанное нарушение. Оповещение
отправляется один раз при активации; устойчивые обновления не спамят получателя.
Завершённая длительность хранится в локальном итоговом журнале.
Webhook получает JSON, а при JPEG — multipart с полями `payload` (JSON-строка)
и `photo`. Фото не снимается специально ради сети: используется существующий
снимок согласно настройкам evidence. Отсутствие/нечитаемость снимка даёт текст,
но неудачная отправка фото не запускает повторную отправку сообщения.

Очередь ограничена 50 элементами, добавление не блокирует UI или vision.
Фоновый поток обрабатывает Telegram, затем webhook. Ошибки/таймауты/5xx и
переполнение дают локальное предупреждение и потерю удалённой копии, не паузу
экзамена и не потерю локального журнала. Перенаправления HTTP отклоняются.
**Автоповторов и сохраняемой очереди нет**: восстановление сети не досылает
пропущенное. При закрытии ожидание worker ограничено двумя секундами;
выполняющийся запрос продолжает подчиняться своему сетевому таймауту.

Для PDF нужны одновременно `reporting.send_pdf_to_telegram = true`,
`remote.enabled = true` и `remote.telegram_enabled = true`, а также создание
PDF. Отчёт может содержать фото лица и снимки событий. Включение передачи
раскрывает эти материалы получателю и, при Telegram, сервису Telegram.
Предупреждения не содержат реквизитов/текста ответа сервера и не увеличивают
число событий проверки. Подробнее: [REGISTRATION_REMOTE.md](docs/REGISTRATION_REMOTE.md).

## 15. Модели и производительность CPU

| Локальный файл | Назначение |
| --- | --- |
| `models/yolo11n.onnx` | YOLO11n COCO, человек (0) и мобильный телефон (67). |
| `models/face_landmarker.task` | Google MediaPipe Face Landmarker, ориентиры лица/радужек. |

Источники, закреплённые версии, SHA-256 и ограничения лицензирования указаны
в [models/README.md](models/README.md). Бинарные модели не хранятся в Git;
EXE включает подготовленные локальные файлы. Нет модели — мониторинг недоступен,
а не скрытая загрузка из сети. ONNX-замена должна соответствовать float32 NCHW,
batch 1, COCO и сырому выходу `[1,84,N]` или `[1,N,84]` без встроенного NMS.
Экспорты segmentation/pose, произвольный порядок классов и end-to-end NMS
текущим адаптером не поддерживаются.

Обычно запрашиваются 1280×720 и 30 FPS, но драйвер может дать 640×480 или
другую частоту. Исходный размер виден в метриках; увеличение preview не
увеличивает разрешение глаз. `camera_backend = "auto"` пробует Windows MSMF,
DirectShow и стандартный вариант. Меняйте backend/индекс только при необходимости.

Захват хранит последний кадр, один inference-worker ограничивает память.
YOLO планируется до 5 Гц, MediaPipe до 12 Гц; фактическая скорость зависит от
CPU. Совмещённые события требуют свежих результатов того же кадра: новая
обработка лица не делает старую детекцию телефона свежей. Рамки preview могут
немного отставать. `yolo_input_size=416` работает для динамической модели;
фиксированная модель использует экспортированный размер, показанный в метриках.

CPU ONNX Runtime обязателен и включён. `prefer_gpu=true` лишь выбирает CUDA,
если совместимый provider отдельно установлен; ошибки приводят к CPU fallback.
MediaPipe работает на CPU. Отсутствие NVIDIA не мешает запуску.

```powershell
.\.venv\Scripts\python.exe scripts\benchmark.py --camera-only --seconds 10 --output artifacts/camera-test.json
.\.venv\Scripts\python.exe scripts\benchmark.py --seconds 20 --output artifacts/benchmark-cpu.json
.\.venv\Scripts\python.exe scripts\benchmark.py --models-only --seconds 10 --output artifacts/models-only.json
```

Benchmark принудительно использует CPU и показывает FPS захвата, среднюю/p95
задержку YOLO и MediaPipe, совмещённую частоту, CPU и память. `--models-only`
работает на искусственном пустом кадре и не измеряет точность/скорость живой
камеры. Сохраняются числовые показатели, не видео. Уменьшайте частоту inference
и размер динамической модели по реальному замеру; предел свежести должен быть
выше рабочего интервала, но всё ещё обнаруживать отказ за разумное время.

```text
assets/                      # Встроенный quiz.json

src/proctoring/

```

| Модуль | Ответственность |
| --- | --- |
| `vision/camera.py` | Захват в фоне, последний кадр, переподключение. |
| `vision/yolo.py` | ONNX provider, letterbox, COCO-фильтры, NMS. |
| `vision/face.py`, `calibration.py` | Ориентиры, глазные признаки, поза, ссылки сессии и классификация. |
| `vision/alignment.py`, `collection.py` | Допуск положения и ограниченный по времени сбор целей. |
| `vision/rules.py`, `types.py` | Нормализованные наблюдения и геометрия поднятого телефона. |
| `vision/monitor.py`, `health.py` | Расписание обработки, heartbeat, ошибки и свежесть. |
| `events/`, `session.py` | Порог/гистерезис, монотонное время, независимые причины паузы. |
| `audio/monitor.py` | Чтение микрофона, RMS и состояние quiet/speak/ready. |
| `ui/audio_check.py`, `window.py` | Отображение числового уровня и настройка до экзамена. |
| `storage/remote_dispatcher.py` | Ограниченная очередь сетевых копий. |
| `storage/report_generator.py` | PDF в фоне, встроенные миниатюры и итоговые правила. |
| `security/` | Проверяемое владение hook отдельным helper и гарантии освобождения. |

Vision формирует наблюдения, а не предупреждения напрямую. Controller передаёт
свежие данные существующему автомату событий и следит за здоровьем/сессией.
Аудио имеет отдельный поток наблюдений, поэтому его обновления не очищают
и не продлевают события камеры. JPEG, PDF, сеть и аппаратное чтение вынесены
из UI. Так сохранены независимые границы CV, интерфейса, защиты и хранения.

## 18. Сборка Windows EXE

Сборка выполняется на Windows из подготовленного окружения проекта. Перед
ней нужны обе локальные модели и Qt WebEngine. Существующая сборочная версия
PyInstaller — **6.22.3**; при отсутствии устанавливайте официальный пакет.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.lock
.\.venv\Scripts\python.exe -m pip install pyinstaller==6.22.3
.\.venv\Scripts\python.exe scripts\fetch_models.py
.\.venv\Scripts\python.exe scripts\build_windows.py
```

Результат — два файла в `dist/LocalProctoring/`. Конфигурация переносится из
`config/protected-demo.toml` с путями для встроенных ресурсов и локальных
результатов. Настройки и реквизиты сохраняются, не печатаются и не встраиваются
в EXE. Повторная сборка **сохраняет существующий** конфиг поставки. Только
если намеренно нужно заменить его текущим protected-demo, используйте:

```powershell
.\.venv\Scripts\python.exe scripts\build_windows.py --replace-config
```

Проверка сборки без камеры/микрофона, реальных HTTP-запросов и блокировки:

```powershell
Set-Location .\dist\LocalProctoring
.\LocalProctoring.exe --package-smoke-test C:\path\to\verification-output
```

Smoke-проверка включает реальный CPU inference на сгенерированном кадре,
локальную страницу WebEngine, audio-импорты и PDF. Аудит выполняется отдельно
на активном разблокированном рабочем столе. Закройте другие экземпляры приложения
и отпустите Ctrl/Shift/Alt/Q перед ним; он не включает подавление клавиатуры.

Отдельный аудит из папки сборки:

```powershell
.\LocalProctoring.exe --validate-protection
```

Обычный запуск с выбранной полной конфигурацией:

```powershell
.\LocalProctoring.exe --config C:\path\to\private-config.toml
```

Последняя команда запускает само приложение, а не smoke-проверку. Использование
камеры, микрофона, сети и ограничений определяется указанной конфигурацией.

Версии зависимостей, уведомления сторонних пакетов и манифест моделей входят
в EXE; исходные метаданные сборки находятся в `build/portable/`. Не считайте
lock-файл точным перечнем уже созданной EXE: например, `requirements.lock`
фиксирует NumPy **1.26.4**, тогда как метаданные существующей сборки содержат
**2.4.6**. Это зафиксированное различие окружений. Успешная проверка этой EXE
не означает отдельно выполненную чистую переустановку по lock-файлу.
Подробнее: [WINDOWS_BUILD.md](docs/WINDOWS_BUILD.md).

<a id="troubleshooting"></a>

## 19. Устранение неполадок

| Симптом | Что проверить |
| --- | --- |
| EXE долго не показывает окно | Первичная распаковка большого пакета; доступность записи/временной папки, отсутствие второго экземпляра. Не удаляйте config во время старта. |
| Изменённый параметр не действует | Редактируется ли config рядом с EXE или именно файл `--config`; перезапущено ли приложение; нет ли повторной секции TOML. |
| Ошибка конфигурации | Тип/диапазон, кавычки Windows-пути, неизвестный ключ, обязательные секции, правильный формат PIN. Не публикуйте файл с реквизитами целиком. |
| Камера недоступна | Windows-разрешение настольным приложениям, занятость камеры, `camera_index`; затем другой `camera_backend` и повтор. |
| Вместо 720p камера даёт 640×480 | Это согласованный драйвером режим. Смотрите реальные размеры/глаза в исходных пикселях, не размер окна preview. |
| «Приблизьтесь» / «Держите оба глаза видимыми» | Положение, свет, исходные размеры глаз, естественная фронтальная поза; используйте крупные планы без сохранения. |
| Сбор не набирает 20 измерений | Конкретные причины отбраковки, максимальные 6 секунд, глазная видимость/свежесть. Повторите текущую цель либо соберите новую базу. |
| Сбор завершён, fit отвергнут | Сравните медианы, осевые разбросы и вклад pixel/constant/spread. Овал и число кадров не доказывают разделимость. |
| Gaze UNKNOWN | Может означать моргание, закрытые/перекрытые глаза, неоднозначную геометрию или выход из области ссылок. Не заменяйте его CENTER. |
| Ложное `gaze_down` при чтении | Разделите глазную метку и `head_down`, проверьте pitch/yaw/roll и положение камеры; затем свежие цели и обычное чтение. |
| Микрофон не показан | Проверьте `[audio] enabled = true`; в поставленной protected-сборке он был выключен. |
| Микрофон недоступен/не реагирует | Вход по умолчанию Windows, разрешения, mute/усиление, повтор устройства, звук обычной громкости. |
| Слишком шумно / нет готовности аудио | Тихие 2,5 с и отдельная речь по команде, числовые RMS/порог, границы 0,05–0,40; не путайте запасную добавку с абсолютным порогом. |
| Нет модели / ONNX не запускается | Наличие файлов и SHA-256, конфигурационные пути, совместимый сырой COCO-выход и CPU provider. |
| Низкий FPS / stale | Запустите CPU benchmark; уменьшите частоту inference/динамический размер. Не маскируйте зависание бесконечным freshness-пределом. |
| LMS уходит на заблокированный адрес | Добавьте только требуемый точный доверенный хост авторизации; проверьте несовместимость popup/SSO. |
| Нет `QtWebEngineWidgets` из исходников | Установите `requirements-browser.lock` в ту же `.venv`; пустой URL сохраняет native quiz без WebEngine. |
| Аудит защиты не проходит | Активный разблокированный desktop, отпущенная аварийная комбинация, отсутствие второго экземпляра, свежая сборка/путь/отчёт. Не обходите gate. |
| Нет Telegram/webhook | Переключатели, правильный получатель, права бота, таймауты и `remote_warnings.jsonl`; доставка не имеет повторов. |
| PDF без снимка | Включены ли snapshots, был ли подходящий кадр, завершилась ли запись; отсутствие снимка законно для некоторых событий. |
| После выхода идёт формирование PDF | Нормальное закрытие может дождаться безопасного завершения Qt PDF-worker; защита должна быть уже освобождена. |

Изолированный `experiments/gaze_tracking_demo/` использует собственную `.venv`
и upstream GazeTracking/dlib. Ошибка сборки dlib означает необходимость
официальных Windows-инструментов компиляции, указанных в README эксперимента;
не ставьте случайные сторонние binary wheels и не меняйте основную `.venv`
ради него. Этот эксперимент не заменяет production-калибровку и не входит
в обязательный запуск приложения.

<a id="limitations"></a>

## 20. Ограничения и дополнительная документация

- Телефоны могут теряться при малом размере, перекрытии или плохом свете;
  изображения людей на экранах/плакатах могут давать ложные детекции.
- Очки, отражения, расстояние, веки и движение влияют на ориентиры глаз.
  Успешный fit или тест на синтетике не устанавливает человеческую точность.
- `head_down` — отдельная эвристика позы относительно камеры; она не доказывает
  наличие телефона/заметок. Порог зависит от установки камеры и естественной позы.
- RMS не распознаёт речь, сравнение формы лица не подтверждает личность,
  экспериментальные признаки возле уха не являются проверенным детектором.
- Проверка свежести по прибытию кадров может не обнаружить драйвер, который
  выдаёт замороженное изображение как новые кадры.
- Ограничения Windows временны и ограничены возможностями обычного приложения;
  это не защищённая от обхода промышленная kiosk/anti-tamper система.
- Серверный таймер и сдача внешнего экзамена независимы от локального таймера.
  Удалённые уведомления могут теряться, локальные материалы остаются основными.
