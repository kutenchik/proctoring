# Stage 2 synchronization contract (v1)

All paths below use `/api/v1`. Student calls use the attempt Bearer credential
and `X-Device-Secret` (a separately generated 256-bit token, kept in Windows
user-scoped DPAPI storage bound to the original machine). Teacher mutations keep
the existing cookie, CSRF and exact Origin requirements. No answer key or device
secret appears in teacher/student renderer projections.

## Admission, start and recovery

- `POST /student/admit` adds `admission_id` (UUID hex), `device_id` (UUID hex),
  `device_secret` and `credential` (both random URL-safe tokens, at least 32
  decoded bytes). The client persists these **before** sending. An identical
  admission retry returns the same attempt; changed identity/code/credentials
  conflict. These fields are optional for legacy Stage 1 clients only.
- `POST /student/start` with `{start_key,session_id}` authorizes preparation-time
  start, without asserting the local exam began. `session_id` is the durable
  `session-<uuidhex>` chosen before this call. Repeated identical requests return
  the authorization, including after the initial deadline. A different key or
  session cannot create another timer.
- `POST /student/start/confirm` with `{start_key,session_id,started_at}` confirms
  the existing local start after its durable checkpoint. The timestamp is ISO
  with offset. Repeated confirmation is idempotent. GET `/student/attempt`
  reconciles the server state and never starts the local timer itself.
- `POST /student/interrupted` with `{interruption_id,session_id,reason,checkpoint}`
  records an unexpected closure. `checkpoint` contains `elapsed_seconds`,
  `remaining_seconds`, `answers` (stable question IDs to selected option ID lists),
  and `pause_reasons` (ASCII strings). A teacher must then explicitly authorize
  recovery. Ended attempts, including terminal emergency exits, cannot recover.
- `POST /attempts/{id}/recovery/authorize` (teacher) with
  `{interruption_id,reason}` creates a grant tied to that interruption and device.
- `POST /student/recovery/consume` with `{grant_id,session_id}` returns an
  idempotent recovery authorization for the original attempt/session; it does
  not assert that local readiness checks passed or the timer resumed.
- `POST /student/recovery/confirm` with `{grant_id,session_id}` confirms the
  already persisted local resume. Another unexpected closure requires a new
  interruption and grant. GET attempt includes `lifecycle`, `start_key`,
  `session_id`, `recovery:{interruption_id,grant_id,state,checkpoint}` and sync
  status in addition to the Stage 1 admission envelope.

These intermediate states reconcile request loss; they do not claim distributed
atomicity or make student-reported timing tamper-proof. Necessary camera/gaze and
protection readiness stays in Python. Emergency termination remains terminal.

## Immutable records and bounded files

- `POST /student/sync/records`: `{session_id,records:[{sequence,record}]}`.
  `sequence` is the zero-based local events.jsonl line number; records retain
  original event/session IDs. Up to 100 records / 512 KiB per batch. Duplicate
  identical sequence payloads are acknowledged, changed payloads conflict;
  batches may arrive out of order. No new alert is generated by synchronization.
- `POST /student/sync/manifest`: `{manifest}`. The immutable document is:
  `{version:1,attempt_id,session_id,ended_at,end_reason,record_count,
  identity_required,items:[{id,kind,relative_path,required,status,size,sha256,error}]}`.
  IDs are stable ASCII `[A-Za-z0-9_-]{1,96}`. `kind` is one of `session`, `events`,
  `summary`, `answers`, `original_pdf`, `reference`, `snapshot`. `status` is
  `present`, `missing_error`, `disabled`, or `optional_absent`; absent sizes and
  hashes are null, `error` is null or a bounded descriptive string. Relative
  paths are metadata, never server filesystem destinations.
- Mandatory kinds are session/events/summary/original_pdf; native attempts also
  require answers. `identity_required=true` requires reference. A missing error
  never satisfies a required item. Available references must be included even
  when optional. Snapshot policy disabled requires a disabled marker; enabled
  snapshots referenced by the journal/summary must be declared. No config,
  calibration export, raw audio/video or screen recording kind is accepted.
- Manifest digest is SHA-256 of UTF-8 JSON with sorted keys, no extra whitespace,
  `ensure_ascii=False`, `allow_nan=False`. Identical retries are idempotent. A
  replacement manifest may repair missing/error material before receipt; it
  cannot rewrite already-present immutable items or a completed receipt.
- `POST /student/sync/files/{item_id}/chunks`:
  `{manifest_sha256,offset,data_base64}`. Chunks contain at most 256 KiB decoded;
  offset must match the persisted byte frontier, or match an already stored
  identical range. Return `{item_id,received_bytes,complete}`. The item is only
  complete after whole-file size/SHA/type verification and fsync persistence.
- `GET /student/sync/status` returns `{status,manifest_sha256,files:[{id,
  received_bytes,complete}],record_sequences,receipt,missing,server_time}`.
- `POST /student/sync/complete` with `{manifest_sha256}` rechecks all declared
  present files, required material and exact journal record equivalence; returns
  `{receipt}` only after the complete bundle is verified and committed. Receipt:
  `{version:1,receipt_id,attempt_id,session_id,manifest_sha256,verified_at,
  file_count,record_count,complete:true}`. GET status can recover a lost response.

Missing required PDF/reference/journal cannot be converted into success through
an error label. Local cleanup requires ended state + this exact matching receipt
+ all expected hashes/items, never a per-file HTTP 200. Server storage is private.

## Teacher/server integration points

The server exposes `app.state.sync` and registers Stage 2 routes through a helper
with `owner(request,mutate)` and `credential(request)` functions. Root-owned
review routes can be registered separately with the same helpers.

`SyncService.teacher_detail(owner,attempt_id)` provides owned attempt/sync state,
manifest, immutable `records:[{sequence,record}]`, safe files metadata, server
result verification and receipt; it excludes device/attempt credentials and quiz
answer keys. `SyncService.evidence_file(owner,attempt_id,item_id)` returns a
validated private path, media type and download filename only after ownership/persistence checks.
`SyncService.require_complete(connection,attempt_id)` enforces ended + verified
receipt for final review. Raw tables: `sync_attempts`, `sync_records`,
`sync_manifests`, `sync_files`, `sync_receipts`, `recovery_grants` (migration 002).
Root owns review/report tables in migration 003.

Retention runs only by explicit CLI `python -m proctoring_server retain` and
deletes completed **fully received** materials 30 days after actual manifest
completion time. If the server is off, cleanup waits for the next invocation.
Teacher early deletion `POST /attempts/{id}/materials/delete` requires
`{confirm:true,reason}` and the same completion/receipt gate, and remains audited.
Minimal tombstones/audit metadata remain; file access and finalization are denied
after deletion. No active/incomplete attempt is deleted by admission-window age.
Deletion commits `deletion_pending` before removing the exact validated private
attempt directory. Reads/uploads/report writers are blocked during that phase;
an interrupted deletion can be retried. Purge also removes raw records, manifests,
review histories, manual-observation content and frozen conclusion/report content.
Minimal conclusion identity/decision/version and explicit deletion audit remain.
The historical receipt remains a tombstone, never a currently complete status.

Start authorization blocks preparation extension and repeat admission until the
same attempt is reconciled or ended. A replacement never resumes the old exam.
An ended old attempt may still authenticate solely for evidence synchronization
after the teacher grants a repeat; otherwise old active credentials stay rejected.
All uploaded JPEGs and PDFs are structurally parsed, in addition to size and
SHA-256 verification. A matching signature alone does not count as a valid file.

Recovery confirmation includes `started_at` (the original durable local
`session_started` timestamp). It is required if the first start confirmation was
lost before the server recorded it. An existing confirmed start time stays fixed.
Per-record session IDs, when present, must match; legacy lines without the field
remain verbatim, bound by the authenticated batch and complete canonical journal.

Evidence-only expiry exception: `/student/sync/{records,manifest,status,complete}`
and file chunks accept an expired attempt bearer **only together with the original
device secret and an already authorized canonical session**. They cannot create a
start authorization or recovery grant. All start/recovery/ordinary admission reads
retain credential expiry checks. An ended outbox need not replay an expired start
confirmation first: complete bundle verification reconciles a missing start ACK
from one consistent original `session_started` timestamp in the final lifecycle
(or explicit summary `started_at`), never a new timer. Server retention still uses
the actual completion time, so a very late complete upload may be immediately due
for the next explicitly invoked retention cleanup.

Teacher event review, reviewed-report endpoints and XLSX schema are defined by
the separate root-owned review module. Student sync never receives those records.

## Teacher review and reports

- `GET /attempts/{id}/review`: `{attempt,exam,sync,events,groups,
  manual_observations,conclusion,conclusion_history,unreviewed_count,can_finalize}`.
  Events retain raw stable identities and latest presentation plus full review
  history. Groups relate the same event type/category within ten seconds, with
  at most 100 records per presentation group to fit an atomic bulk request, without
  merging or removing originals. Technical records remain separate from behavioral
  observations; unreviewed counts concern behavioral observations.
- `POST /attempts/{id}/reviews`: `{items:[{event_id,expected_version,
  decision,comment}]}`. One to 100 items, atomically checked and saved. Decisions:
  `not_reviewed`, `confirmed`, `false_positive`, `insufficient_evidence`.
  `confirmed` means observation confirmed, not an academic violation.
- `POST /attempts/{id}/manual`: `{category,description}`. Server supplies author,
  actual creation time and `during_exam`/`later_review` from recorded attempt state.
- `POST /attempts/{id}/manual/{observation_id}`:
  `{expected_version,category,description,cancelled}`. Corrections/cancellation
  append versions; no evidence image is generated.
- `POST /attempts/{id}/conclusions`: `{expected_version,decision,comment,
  confirm_unreviewed}`. Decisions: `none_confirmed`, `violation_confirmed`,
  `insufficient_evidence`. Requires ended + verified complete receipt. If behavioral
  observations are unreviewed, an explicit true confirmation is required; their
  count is frozen into this conclusion and reviewed PDF. Returns the detail with
  report pending; generation runs in a background task. Event/manual edits mark
  the latest conclusion for reconsideration without changing its historical PDF.
- `GET /attempts/{id}/reports/original`: preserved uploaded original PDF.
- `GET /attempts/{id}/reports/reviewed/{version}`: immutable reviewed PDF version.
- `POST /attempts/{id}/reports/reviewed/{version}/retry`: retry failed/pending
  report generation, without changing the frozen review snapshot.
- `GET /exams/{id}/export.xlsx`: typed, teacher-owned consolidated attempt export.
  Student strings are explicitly spreadsheet text, never executable formulas.

All mutations use optimistic versions (zero before the first version). Conflicts
return 409 and require refresh. Student endpoints expose no teacher decisions or
reviewed PDFs. Existing local scores remain unchanged by conclusions; server
recalculation and discrepancies are separately recorded.

Only the five evidence-sync endpoints accept an expired bearer with its matching
device secret for an already start-authorized canonical session. Admission, start
and recovery keep expiry enforcement. A late complete bundle can reconcile a lost
start confirmation using the one original local start timestamp; it cannot create
a new start or reset the timer.
# Stage 4B active-snapshot extension (2026-10-14)

Event-associated JPEGs may now be declared and uploaded before the final manifest
using authenticated `/student/sync/snapshots` and
`/student/sync/snapshots/{item_id}/chunks` under the existing API prefix.
Migration 005 binds each provisional file to its original attempt/event. Policy,
session, credential/device and consent v3 are checked. Identity, size and hash
are immutable, and final manifests must retain every provisional file unchanged.
An early acknowledgement is never a complete receipt or deletion authorization.
Existing ended-attempt, complete-bundle and matching verified receipt requirements
remain authoritative. Existing retention timing is unchanged.
